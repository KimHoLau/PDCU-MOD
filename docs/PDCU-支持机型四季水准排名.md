# PDCU 四季移植：支持机型水准排名（2026-11，加权评分）

日期：2026-10-29（2026-11-02 改为加权评分，并加入 K20D；2026-11-02 晚加 K10D；2026-11-02 深夜加 K-7；2026-11-03 加 \*ist DL；2026-11-06 加 K-5；2026-11-06 加 K-r；2026-11-07 加 K-x）

范围：工具/内置数据目前支持的 **24 台机身**（KF 计入；v2.3 加入 MX-1，v2.4 加入 K-1 Mark II，v2.8 加入 K20D，v2.9 加入 K10D，v2.10 加入 K-7，v2.12 加入 \*ist DL，2026-11-06 加入 K-5 与 K-r，2026-11-07 加入 K-x）。
判据：**加权评分**——数据出身 30% + 端到端验证 50% + 实现代价 10% + 风格残差 10%。
档位（S/A/B）仍按“Y 从哪来”分类，但**名次按分数排序，不再按档连续**。

## 0. 结论

1. **24 台全部可用**，四季风格与 KF / K-7 原生的残差都在 **0–1.07×10⁻⁴**（≤0.88 个 Q13 LSB），
   画面上都不可见——这份排名衡量的是“数据与证据有多可信”，不是画质。
2. 前四名：**KF 100.0 → K-70 93.5 → K-1 89.0 → K-1 Mark II 87.5**，都是 S 档。
3. **新加入的 K-5 排到第 11（75.8），K-r 排到第 12（75.6）**：两台都是 0x021B 真值、
   12 参数、无需重建记录布局；PDCU 5.10.2.2 已实测菜单与四季渲染，但只有单场景，
   验证分 70。K-5 的基准与 K-3 / K-5 II 相同，K-r 的 Y 独立（与 K-5 差 1.57×10⁻¹）。
4. K-50（76.8，第 10）仍是 B 档最高：九机同场景把验证分拉到 90，压过 A 档的
   **K10D（75.4，第 13）**、**K-7（74.7，第 14）**、**K20D（74.2，第 16）** 与
   **645D（73.2，第 18）**。
5. **K-x 以 73.4 排到第 17**：它的 0x021B 与 K-7 同风格表，所以 donor 用 K-7；
   11→12 重建 + 两张表搬进块内空闲区，残差 5.6×10⁻⁵。
6. 尾部是 **MX-1（51.2，第 23）与 Q7（50.8，第 24）**：远线外推，数据不是 Pentax 官方值。
7. **分差 < 2 分视为同级**（K-3 与 K-3 II 同分；K-30 与 K-01 差 0.1；K-5 与 K-r 差 0.2、
   K-r 与 K10D 也差 0.2；K-x 与 K20D 差 0.8）。

## 1.1 评分口径

### 权重

| 维度 | 权重 | 为什么给这个权重 |
|---|---:|---|
| 端到端验证 | **50%** | 所有机型的四季都是“同一套 KF 矩阵乘 Y”，风格像不像由 R 决定；但“这条路径有没有被真正跑通”只能靠实测。历史上出问题的地方都是验证没覆盖到的角落（K20D 的填充值 bug 就是一次没被验证覆盖的改动）。 |
| 数据出身 | **30%** | 决定 Y 是“机身真值”（0x021B）还是“外部推算”（ColorMatrix2）。这是数据可信度的上限。 |
| 实现代价 | **10%** | 布局手术越大，出错面越大：新建标签 < 11→12 参数重建 < 5→12 参数重建 + 块内搬表 < 8→12 参数 + 整块搬迁。 |
| 风格残差 | **10%** | 全部机型都 < 1 个 Q13 LSB，肉眼无差，因此权重压到最低，只用来区分同分。 |

### 各维度的取值锚点

| 维度 | 锚点 |
|---|---|
| 数据出身 | 机内原生 **100**；等价原生（与 donor 基础矩阵逐字节相同）**95**；机身 0x021B 真值 **85**；ColorMatrix2 近线推算（Y 与 K-3 差 <1×10⁻⁴）**60**；远线外推（≥1×10⁻¹）**30** |
| 端到端验证 | donor 本体 **100**；九机同场景（Y 为真值/近线）**90**；九机同场景但有 CM2 告警 **80**；PDCU 菜单 + 四季渲染 + 方向 + As Shot（单场景）**75**；PDCU 菜单 + 四季渲染（单场景）**70**；PDCU 菜单 + 渲染 + 比值 + As Shot（远线）**65**；PDCU 渲染复核 **55**；九机同场景但 Y 为远线 **55**；未 PDCU 实测 **45** |
| 实现代价 | 12 参数、无需改布局 **100**；新建两个标签 **85**；11→12 参数重建 **75**；5→12 参数重建 + 块内搬表 **70**；11→12 参数重建 + MakerNote 整块搬迁 **68**；8→12 参数 + MakerNote 整块搬迁 **60** |
| 风格残差 | 100 × (1 − ΔR / 1.22×10⁻⁴)：0 → 100，5.7×10⁻⁵ → 53.1，5.8×10⁻⁵ → 52.5，1.07×10⁻⁴ → 12.3 |

### 权重敏感度（诚实说明）

权重是判断，不是物理量。同样四列分数，把**出身提到 45%、验证降到 35%**，K20D（75.8）
就会回到 K-50（72.3）之前——也就是退回上一版的“出身优先”结论。现在的权重是刻意
按**证据优先**定的：既然所有机型的残差都在 1 LSB 内，真正拉开信任差距的就是
“这条路径被端到端验证过几次、覆盖了什么”。改权重等于改结论，所以把这一条写在这里。

## 2. 档位：按“Y 从哪来”分类（与名次分离）

### S 档：原生或等价原生（4 台）

- **KF**（#1）：四季表就是从 KF 机内读出来的，是全部对比的基准。
- **K-70**（#2）：KF 与 K-70 共用同一套 21 个基础矩阵（逐字节相同），Y=I，
  写进去的四季矩阵就是 KF 原值；残差 0，属于“等价原生”。
- **K-1**（#3）：用的是 K-1 自己的机内四季表。它的 7.3×10⁻⁵ 是
  “两张原生表之间的量化差”，不是移植误差。
- **K-1 Mark II**（#4）：28 条模式记录和 21 个基础矩阵与 K-1 **逐字节相同**，
  Y=I，写入的就是 K-1 的原生四季矩阵；7.3×10⁻⁵ 同样是与 KF 原生表之间的
  量化差。PDCU 实测见 [PDCU-K1II-四季移植.md](PDCU-K1II-四季移植.md)。

### A 档：机身 0x021B 基准精确校准（15 台）

这 15 台都有 `0x021B` 基准矩阵。对与 KF 同表的机身，工具算
`Y = inv(M_KF[0])·M_body[0]`；K-x 与 K-7 同表，算 `Y = inv(M_K7[0])·M_body[0]`。
再把对应 donor 的四季矩阵乘上 Y。数学上就是 Pentax 生成各机身表的做法，所以是“精确解”。

- **K-3 / K-3 II / KP**（#5–#7）：九机同场景，CM2 复核 pass（K-3、KP）；
  K-3 II 的矩阵表与 K-3 只差第 2 号一格，验证分相同，与 K-3 并列。
- **K-S2 / 645Z**（#8–#9）：实际渲染仍以 0x021B 为准，四季是精确的；但它们的
  DNG ColorMatrix2 与自身 0x021B 基准不一致（1.3×10⁻² / 2.7×10⁻³），CM2 复核
  告警，验证分从 90 降到 80，因此落到 82 分一档。
- **K-5**（#11）：Y 来自自身 0x021B；基准 #0 与 K-3、K-5 II 逐字节相同，
  Y 与 K-3 完全相同，残差 5.7×10⁻⁵。验证覆盖 PDCU 5.10.2.2 菜单、四项四季
  渲染（单场景，逐项核对 HARUBENI/KATEN/KYUSHU/FUYUNO）与 As Shot 结构不变，
  但未做 As Shot 逐像素对比，给 70；实现是 12 参数、0x021A 1,068→782 B、
  0x021B 328→400 B 搬到 0x021A 尾部释放的空间，不重建记录布局，给 100。
  合计 75.8，与 K10D（75.4）同级。详见
  [PDCU-K5-四季移植分析.md](PDCU-K5-四季移植分析.md)。
- **K-r**（#12）：Y 来自自身 0x021B；基准与 K-5 不同（Y 差 1.57×10⁻¹），
  残差 6.0×10⁻⁵。验证覆盖 PDCU 5.10.2.2 菜单、四项四季渲染（单场景）与
  As Shot 结构不变，但未做 As Shot 逐像素对比，给 70；实现是 12 参数、
  0x021A 912→782 B、0x021B 328→400 B 搬到释放的尾部，不重建记录布局，给 100。
  合计 75.6，与 K-5（75.8）、K10D（75.4）同级。详见
  [PDCU-Kr-四季移植分析.md](PDCU-Kr-四季移植分析.md)。
- **K10D**（#13）：Y 来自自身 0x021B；CM2 复核**不通过**（0.27，旧转换器写的
  ColorMatrix 元数据），但 PDCU 只乘 0x021B、不读 ColorMatrix（已用只改一处的
  DNG 实测证明），所以数据仍是机身真值。残差 5.6×10⁻⁵；验证覆盖 PDCU 菜单、
  四项渲染、marker（纯 R/G/B/单位矩阵）与 As Shot **变准**（105.3/108.1/100.5 →
  111.0/112.4/103.2，机身 JPEG 112.0/113.3/104.8），单场景给 75；实现是
  5→12 参数重建 + 把两张表搬进私有块内的 19 KB 空闲区（文件 +0 B），给 70。
  合计 75.4。
- **K-7**（#14）：Y 来自自身 0x021B；CM2 复核在这份文件上**不通过**（0.31，
  与 K10D 同类的旧转换器元数据），但 K-7 与 KF 的 mode-0 相对风格完全相同
  （1.1×10⁻¹⁶），PDCU 又只乘 0x021B，所以 Y 仍是机身真值。残差 6.2×10⁻⁵；
  验证覆盖 PDCU 菜单、四项渲染、marker 与 As Shot（单场景 75）；实现是
  11→12 参数重建 + MakerNote 整块搬到文件尾（+35,091 B，68）。合计 74.7。
- **\*ist DL**（#15）：2005 年的 6 MP 机身，Y 来自自身 0x021B，max|Y−I| = 0.1625
  （支持机型里最大，校准最不能省）；残差 6.1×10⁻⁵。CM2 与 0x021B 差 0.154，
  是 PDCU 自己写的元数据；PDCU 只乘 0x021B，所以 Y 仍是机身真值。验证覆盖
  PDCU 菜单、四项渲染、marker（#7–#10 换纯红后四项全红、As Shot 逐像素不变）
  与 3008×2008 另存 JPEG，单场景给 75；实现是 5→12 参数重建 + MakerNote
  整块搬到文件尾（+12,925 B），介于 K10D 的块内搬表（70）与 K20D 的
  8→12 整块搬迁（60）之间，给 65。合计 74.5，与 K-7（74.7）、K20D（74.2）同级。
- **K20D**（#16）：Y 来自自身 0x021B，CM2 复核 pass（2.0×10⁻⁵，A 档最好），
  残差 5.8×10⁻⁵。验证覆盖了 PDCU 菜单、四项渲染、方向对照与 As Shot 不变，
  但只有单场景，验证分 75；实现分最低（8→12 参数 + MakerNote 整块搬到文件尾，
  文件 +25,280 B），两项相抵后 74.2。
- **K-x**（#17）：Y 来自自身 0x021B，但 0x021B 与 K-7 同风格表（21 个共有模式，
  最大 1.35×10⁻⁴），所以 donor 用 K-7 而不是 KF；11 参数 / 23 条 → 12 参数 /
  27 条，0x021A / 0x021B 搬进私有块尾部空闲区，残差 5.6×10⁻⁵。验证覆盖 PDCU
  菜单 + 四季渲染（单场景）70；实现 75（11→12 重建 + 表迁移，不搬 MakerNote）。
  合计 73.4。详见 [PDCU-Kx-四季移植分析.md](PDCU-Kx-四季移植分析.md)。
- **645D**（#18）：Y 同样来自自身 0x021B，CM2 pass（4.0×10⁻⁵）；验证是
  单场景的菜单 + 渲染（70 分），实现是 11→12 参数重建（75 分），总分 73.2。
- **K-5 II / K-5 II s**（#19–#20）：数据与 K-3 共用同一张表（出身 85、实现 100），
  但**没有 PDCU 实测**，验证分只有 45，所以掉到 63.1——这是“数据没问题但没验过”
  的典型。

### B 档：ColorMatrix2 推算（5 台）

这 5 台没有 `0x021A`/`0x021B`，Y 只能由 DNG 的 ColorMatrix2 反推：

| 机型 | Y 与 K-3 的差 | 说明 |
|---|---:|---|
| K-01 | 1.50×10⁻⁵ | 离单反校准线最近 |
| K-30 | 2.19×10⁻⁵ | 与 K-01 只差 2 个 Q13 系数 |
| K-50 | 3.65×10⁻⁵ | 与 K-3 的 Y 差 3.65×10⁻⁵；端到端验证最完整 |
| MX-1 | 1.04×10⁻¹ | 1/1.7" 小底；PDCU 菜单 + 四季渲染 + 同场景比值，As Shot 零变化 |
| Q7 | 0.34（矩阵元素） | 1/1.7" 小底，不在单反校准线上，最佳推算 |

K-30 / K-01 / K-50 的四季表彼此只差 2–3 个 Q13 系数（≤1 LSB）。排序按分数：

- **K-50**（#10）：B 档唯一做了**九机同场景**的，验证分 90（与 A 档最高一档持平）；
  虽然出身只有 60，仍以 76.8 排到第 10。它的 Y 与 K-3 只差 3.65×10⁻⁵，
  季节矩阵与 K-3 精确解差 ≤1 LSB（见 [PDCU-K50-K70四季对比.md](PDCU-K50-K70四季对比.md)）。
- **K-30 / K-01**（#21–#22）：只有 PDCU 渲染复核（验证 55），59.6 / 59.5，同分同级。
- **MX-1 / Q7**（#23–#24）：远线外推，出身 30；MX-1 多做了菜单、渲染、比值与
  As Shot（验证 65），Q7 只有九机同场景（55）且残差被打到 12.3 分——
  1.07×10⁻⁴ 已经接近 1 LSB。

### A / B 的边界：K-50 与 K20D 换了位置

上一版按档排时，K20D（A）在 K-50（B）之前；改成加权分后反过来了
（现在 K-50 #10、K-5 #11、K-r #12、K10D #13、K-7 #14、K20D #16、K-x #17）。
两者的数据差别没变，变的是权重：

| | K-50（#10，76.8） | K20D（#16，74.2） |
|---|---|---|
| Y 来源 | ColorMatrix2 反推（出身 60） | 机身 0x021B（出身 85） |
| 端到端验证 | 九机同场景 + K-3 对照（90） | 单场景：PDCU 菜单 + 四项渲染 + 方向 + As Shot（75） |
| 实现代价 | 新建标签（85） | 8→12 参数 + MakerNote 搬迁（60） |
| 交叉校验 | 反推 Y 与 K-3 差 3.65×10⁻⁵，矩阵差 ≤1 LSB | 0x021B 与 CM2 互证 2.0×10⁻⁵ |

**K-50 赢在“测得多”，K20D 赢在“出身正”。** 现在的权重把验证放在第一位，
所以 K-50 在前；这个名次差 2.6 分，属于“同级边缘”，不代表 K-50 的四季更准。
K10D（75.4）落在两者之间：出身与 K20D 相同（0x021B 真值），验证同样是单场景，
但实现更省（5→12 参数重建、块内搬表、**文件 +0 B**，给 70 而不是 60）。
K-5（75.8）与 K-r（75.6）也在这一带：数据同为 0x021B 真值，验证只覆盖单场景的
菜单 + 四季渲染（70），但实现是 12 参数、无需重建布局（100），所以略高于 K10D。

## 4. 边界

1. **分数是判断，不是物理量。** 权重一改名次就变（§1.1 给了敏感度例子）；
   同一组数可以排出不同结论，所以把口径和锚点全部写出来，方便复算与替换。
2. **分差 < 2 分视为同级**：K-3 与 K-3 II 完全同分；K-30 与 K-01 差 0.1；
   K-50 与 K20D 差 2.6，也已经接近这条线。
3. **“同档内的名次不构成可见差别”仍然成立**：所有残差都 < 1 LSB，名次只反映
   证据完整度与实现代价。
4. **K-5 II / K-5 II s（#19–#20）还没在 PDCU 里实测**（当时的分析机没装 PDCU），
   它们的数据与 K-3 共用同一张表；如果只看“数据出身”，这两台应该靠前得多。
   同一张表的 K-5（#11）已在 PDCU 5.10.2.2 上实测，但那是 K-5 这个机型，
   不能直接当作 K-5 II / II s 的验证。
5. **K-30 / K-01（#21–#22）没有同场景定量色差**，样本是街景/舞狮；只用当前表
   重新渲染确认 PDCU 列出并渲染四项。
6. **MX-1 / Q7（#23–#24）是“最佳推算”**，不是官方数据；1/1.7" 小底的色彩空间
   与单反差得远。MX-1 的 Y 与 K-3 差 1.04×10⁻¹，Q7 的 0.34；四季/As Shot 比值
   只能证明相对风格与 KF 一致，不能证明绝对色彩。
7. **只验证 PDCU 5.10.2.2**；Lightroom / Capture One / dcraw 不读 Pentax 四季。
8. **645D（#18）要重建 0x021A 记录布局**才被 PDCU 识别；副作用是 PDCU 对 645D 的
   默认显影会切到 12 参数路径（实测更接近机身 JPEG 预览，2026-11-02 复核见
   [PDCU-645D-KF四季移植.md](PDCU-645D-KF四季移植.md) 第 4.1–4.2 节）。
9. **K20D（#16）的布局改动最大**：8 参数 / 18 字节 → 12 参数 / 26 字节，而且 AOC
   MakerNote 已经排满，整个块要搬到文件尾（文件 +25,280 B，旧块成为无引用
   死区）。新增的 7–9 号槽必须按 `0,0,0,0xFFFF` 填，全填 `0xFFFF` 会把默认显影
   抬亮（已修正）。只验证了一份 DCU 5.10.2 转出的 DNG；2026-11-02 复核实测默认
   显影与原名一致（62.4/51.7/42.1 vs 62.5/51.4/41.9），四季方向与 KF 同向。
10. **K10D（#13）只有一份样本**，而且是旧版/第三方 PEF→DNG（DNG 1.1、
    `Software = K10D Ver 1.31`、`0xC634` 相对偏移）。它的 ColorMatrix2 与 0x021B
    相差 0.27，比 K-S2 的 1.3×10⁻² 大一个数量级——这是文件元数据的问题，
    PDCU 只乘 0x021B，所以四季与默认显影都不受影响（实测默认显影反而更贴近
    机身 JPEG）。若拿这份 DNG 去 Lightroom，色彩会与 PDCU 不同，但那些软件
    本来也不读四季。
11. **K-1 Mark II（#4）只有一份样本**，但它的 28 条记录、21 个基础矩阵与 K-1
    逐字节相同，移植是同一张原生表的直接复用，不存在按 ColorMatrix2 外推的
    不确定度；详见 [PDCU-K1II-四季移植.md](PDCU-K1II-四季移植.md)。
12. **K-7（#14）的结构与 K20D 同型**：AOC MakerNote + 绝对偏移 + 块内排满，
    11 参数 / 24 字节 / 22 条记录。工具重建 12 参数并把整块搬到文件尾
    （+35,091 B），原文件只改 5 B；PDCU 5.10.2.2 实测菜单、四项渲染、marker
    与 As Shot。CM2 与 0x021B 差 0.31（K10D 同类），PDCU 不读 CM2，所以不影响
    四季；详见 [PDCU-K7-KF四季移植.md](PDCU-K7-KF四季移植.md)。
13. **\*ist DL（#15）是目前最老的机身**：5 参数 / 12 字节 / 7 条记录 + 7 个矩阵，
    AOC MakerNote 完全紧排，所以走的是“5→12 参数重建 + 整块搬迁”（+12,925 B）。
    它此前被误判为“四季画面不可控”，真正原因是 PDCU 的风格列表会回绕、键盘
    选行选错了档位；改用 HOME 定位后 marker 证明四季由写入矩阵控制。详见
    [PDCU-istDL-KF四季移植分析.md](PDCU-istDL-KF四季移植分析.md)。
14. **K-5（#11）的 0x021A 尾部 390 B 不是空的**：K-5 II 的同一位置以 0xAA 为主，
    K-5 却是 61 种字节值的非空数据。工具默认的紧凑布局会把这段覆盖掉，PDCU
    5.10.2.2 实测无影响；保守布局（保留 1,068 B 标签、把新 0x021B 放到私有块
    尾部空闲区）尚未做 PDCU 实测。As Shot 只做了结构论证，没有逐像素对比；
    详见 [PDCU-K5-四季移植分析.md](PDCU-K5-四季移植分析.md)。
15. **K-r（#12）的 0x021A 尾部 234 B 也不是空的**：有 11 种字节值；工具默认的
    紧凑布局会覆盖它，PDCU 5.10.2.2 实测无影响，保守布局未测。K-r 的 Y 与 K-5
    不同（差 1.57×10⁻¹），不能照搬 K-5 的 0x021B 矩阵；详见
    [PDCU-Kr-四季移植分析.md](PDCU-Kr-四季移植分析.md)。
16. **K-x（#17）不能照搬 K-r 的路径**：K-x 是 11 参数 / 23 条 / 16 矩阵、无填充，
    必须 11→12 重建并把两张表搬进私有块尾部；数据源也不是 KF，而是与 K-x 同
    风格表的 K-7（21 个共有模式，max 1.35×10⁻⁴）。详见
    [PDCU-Kx-四季移植分析.md](PDCU-Kx-四季移植分析.md)。
